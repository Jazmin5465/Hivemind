# How the detector decides

Generated by `ml/eval/model_report.py` for model `lgbm-synth-fc09a1e5`.

## 1. What the model is

- **LightGBM**, a gradient-boosted tree model: **444 decision trees** (111 rounds x 4 classes) with **10,279 split rules** in total.
- **Classes:** normal, pipeline_leak, pump_degradation, pump_failure.
- **Inputs:** 58 numbers per facility per 5-minute step (see `ml/features.py`).
- **How a prediction is made:** for each class, every tree for that class asks a few yes/no questions about the inputs and lands on a leaf with a score. The scores of all trees for a class are added up, and the four totals are turned into probabilities (softmax). There are no per-input weights as in a linear model: the trees and their thresholds are the model.
- **Trained on:** synthetic: 40 simulated weeks (32 train, 8 validation), simulator calibrated on full_week.
- **The exact model** is the plain-text file `ml/model/lgbm.txt`: every tree, threshold and leaf score.

## 3. Real trees from the model

The first tree of each class (round 1, usually the most influential), top 3 levels. These are the model's actual splits. A leaf's score is added to that class's total; every later tree adds a smaller correction. Compare a tree's leaves with each other: the first tree also carries the class's starting value (how common the class is), so all its leaves can be negative and the higher one still means *more likely*. For example, in the failure tree a fault (`pump_status` > 1.5) scores higher than no fault.

## 4. A short rule set that imitates the model

A single decision tree, **4 levels deep**, trained to copy the model's own calls on 300,000 rows of the synthetic training data (real data never used). It is much easier to read than 444 trees, but it is an **approximation**: the table shows how often it makes the same call as the real model.

| Data | Rows | Same call as the model | normal | leak | worn pump | failure |
|---|---|---|---|---|---|---|
| Held-out synthetic weeks | 177,408 | **99.0%** | 99.0% | 98.9% | 97.6% | 100.0% |
| Real full_week | 30,240 | **98.9%** | 98.7% | 99.9% | 99.5% | 100.0% |

The per-class columns read: of the steps where the model called that class, the share where the rules called it too.

Against the real week's answer key (one row per facility per step): the full model is right **99.1%** of the time, these rules **98.3%**.

```
if pump status (0 stopped, 1 running, 2 fault) <= 1.5:
    if pipeline pressure vs normal (psi), lowest 6 h average <= -15.2 psi:
        if pipeline pressure vs normal (psi), lowest 6 h average <= -178.1 psi:
            if tank level change per hour over 2 h <= +2.95 pts/h:
                -> normal  (100% of the model's calls here)
            else:
                -> normal  (70% of the model's calls here)
        else:
            if pipeline pressure vs normal (psi), 30 min average <= -3.0 psi:
                -> LEAK  (100% of the model's calls here)
            else:
                -> normal  (96% of the model's calls here)
    else:
        if pump flow (fraction of rated), last 2 h of running <= 99.5%:
            if discharge pressure vs normal (psi), last 2 h of running <= -0.7 psi:
                -> WORN PUMP  (99% of the model's calls here)
            else:
                -> normal  (70% of the model's calls here)
        else:
            if pump flow (fraction of rated), 2 h average <= 99.8%:
                -> normal  (74% of the model's calls here)
            else:
                -> normal  (95% of the model's calls here)
else:
    -> PUMP FAILURE  (100% of the model's calls here)
```

How to read it: start at the top, follow `if` when the condition is true and `else` when it is false, and stop at an arrow. The percentage is how often the model itself made that call for the training rows that end there.
